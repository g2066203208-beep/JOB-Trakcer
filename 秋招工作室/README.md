## 数据准确性规则

1. 用户明确说“投了” → 企业层面记为 **已投递**。
2. 公开招聘页能确认的 → 记录“公开岗位池/岗位要求”。
3. 公开链接不能证明用户实际勾选了哪一岗 → **不猜**，标“待核对”。
4. 有唯一岗位ID但标题无法公开解析 → 保留岗位ID，等待个人投递记录核验。
5. 拿到“我的投递”截图/邮件后，立即把实际岗位名称写死。

## 每个岗位必须记录

- 企业
- 岗位
- 公开岗位池
- 地点
- 投递日期
- 当前状态
- 截止/测评/笔试/面试时间
- 简历版本
- JD关键词
- 关键能力
- 个人匹配证据
- 能力缺口
- 企业研究
- 笔试准备
- 面试准备
- 项目故事
- 下一步动作
- 优先级

## 状态流水线

已投递 → 测评 → 笔试 → 一面 → 二面/终面 → HR → Offer

同时允许：拒绝 / 主动结束 / 无反馈。

## 使用原则

1. A级岗位：每天检查并做针对准备。
2. B级岗位：有流程推进时升级。
3. C级岗位：只保留，不占核心准备时间。
4. 不以“投递数量”作为主要指标，看“投递→笔试→面试→Offer”的转化。
5. 每次面试后24小时内写复盘。
