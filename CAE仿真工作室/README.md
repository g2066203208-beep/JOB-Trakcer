## 导航

- \`index.html\`、\`styles.css\`、\`app.js\`、\`data.js\`：静态工作室网站。无构建步骤，可由 GitHub Pages 直接托管。
- \`学习路线.md\`：技能地图、训练顺序、验收标准。
- \`案例/README.md\`：已记录研究案例和未来练习项目的登记规则。
- \`模板/CAE案例记录模板.md\`：每个案例的统一格式。
- \`成果/README.md\`：原始模型、计算、后处理、图表、报告目录规范。
- \`资源库/README.md\`：文献、规范、开源基准与资料使用规则。

## 区分四种状态

| 状态 | 定义 | 可否对外宣称成果完成 |
|---|---|---|
| 规划练习 | 只列出方案/目标，尚无计算材料 | 不可 |
| 研究记录 | 曾有研究/操作/结果记录，但尚未在本工作室形成完整证据包 | 仅可注明来源、条件和待补内容 |
| 待验证 | 已归档文件，但缺少网格独立性、基准对照、结果检查等关键证据 | 不可称“已验证” |
| 已验证可展示 | 模型、参数、求解日志、结果、误差与可复现说明已审查 | 可以在注明范围和限制后展示 |

**重要：** 网页当前案例卡片是已有研究背景的初始索引，不代表已经从原工程库迁入所有模型和数据；\`data.js\` 显示的数字不是本工作室重新计算的结果。

## 工程案例最小闭环

1. 定义真实问题、假设、坐标、单位、几何来源。
2. 留存材料、连接/接触、网格、边界和载荷说明及依据。
3. 记录求解器版本、求解类型、收敛/稳定性与日志。
4. 归档计算输出、可复现的曲线/表格/云图和生成方法。
5. 用解析解、试验、规范或权威基准验证，并说明偏差与局限。
6. 完成技术报告与一页作品集展示卡，经人工核验后改为“已验证可展示”。

## 仓库与文件安全

- Git 不适合存储巨大 \`.odb\`、\`.d3plot\`、\`.sim\` 和原始时程文件：大型或频繁变动的二进制文件优先 Git LFS、Release 附件或有权限的外部对象存储，同时保留索引与 SHA256 校验和。
- 遵守第三方模型、文献和软件协议，不上传商业许可文件、含密数据或无转授权的 PDF。
- 不记录个人软件许可证密钥、账号和真实机构敏感资料。
- 网页的学习进度只在**本地浏览器**保存，不会同步写回 GitHub。新增案例应修改 \`data.js\` 并提交；原模型需要另行整理入库。
