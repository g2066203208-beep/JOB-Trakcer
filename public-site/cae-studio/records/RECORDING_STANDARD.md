# 全过程操作记录标准

本记录规范适用于课程复现与后续独立验证案例。每一项未完成的内容保持“待补录”，不得凭最终模型反推成已经执行过的点击记录。

## 每个案例必须包含

1. 定位：案例编号、行业方向、适用岗位、工程问题、分析类型、预期交付。
2. 来源：课程/文献/标准、原始文件名与 SHA-256、原作者、本人的工作、允许公开的材料范围。
3. 环境：软件版本、插件、求解器、单位制、运行目录、脚本版本、硬件与并行设置。
4. 假设：几何简化、材料本构、连接方式、边界与载荷、忽略因素、适用范围。
5. 全过程：几何 → 材料 → 接触 → 网格 → 约束与载荷 → 求解 → 后处理 → 验证 → 总结。
6. 证据：可编辑工程、脚本、执行日志、原生截图、结果数据、错误与修复记录。
7. 结论：数值含义、作用范围、单位、收敛与平衡、差异、不能得出的结论。
8. 求职表达：30秒介绍、3分钟技术说明、面试追问、本人完成部分及待补强能力。

## 每一步的固定字段

|字段|填写要求|
|---|---|
|步骤 ID|例如 L07-CONTACT-003，前后步骤可互相引用|
|记录类型|原始执行 / 重新演示补录 / 待执行；不得混写|
|目的|为什么做这一步，解决什么问题|
|前置状态|打开哪个工程、哪个系统、哪个分析步；引用保存点|
|菜单路径|模块 → 树节点 → 右键菜单/工具栏 → 对话框|
|选择对象|实体、面、边、节点/命名选择；附高亮图，记录 ID 仅辅助，不能只靠 ID|
|输入参数|名称、数值、单位、坐标系、时间步、来源与理由|
|操作细节|点击、键盘输入、切换、应用；脚本操作记录原始 API|
|预期现象|树状态、几何/网格变化、界面显示|
|实际现象|真实执行观察，不能复制预期现象代替|
|证据|原生图或界面截图文件、日志行、脚本与源文件哈希|
|保存点|工程路径/版本，确保相关 _files 一并保存|
|核查|如何判断正确；网格、反力、单位、时间步等|
|失败与恢复|错误原文、原因假设、验证动作、修复后证据|

## 目录约定

- 原始输入单独保存，不覆盖。
- 工作工程采用全英文 D 盘路径：D:/codex/cae_courses/lessonXX/。
- evidence/ 保存模型清单、结果状态、云图、过程截图和数值。
- scripts/ 保存实际执行过的 Python 与 Workbench journal。
- GitHub 公开页保存原创记录、本人运行生成的图和轻量数值；大工程与课程原视频仍在本地保留。
- 将来增加 step-records.jsonl，每执行一步追加一条，保存真实时间戳。已有历史只引用实际日志时间，不编造录屏或鼠标点击。

## 分级验收

工程恢复、模型核对、重新求解、结果读取、数值验证、逐步骤手册验收分别记录。只有这些阶段都完成，才能标记“完整复现”。没有分析定义的几何课不强行添加任意载荷。
